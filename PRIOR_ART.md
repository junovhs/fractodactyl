# Mandatory prior-art search and evidence ledger

**Hard gate for all NEW research questions and experiments after 2026-10-12.** Applicable to this documentation-only research branch, including incremental optimizations and follow-ups. See [operating rules](AGENTS.md), [method](METHOD.md), [P template](TEMPLATES/QUESTION.md), [R template](TEMPLATES/RESULT.md), and [proof-of-done](PROOF_OF_DONE.md).

## BEFORE writing code or running a new numerical experiment

1. **Actually execute external searches**, not just recall that a technique is classical. Run **at least three distinct, targeted queries**: the exact mathematical mechanism and synonyms; the intended application/domain; and methods, specialized solvers and prior benchmarks that could supersede the idea. Search a real indexed literature/web source available in the environment (such as web search, Crossref or publisher repositories). A planned search string is **not** a completed search.
2. **Read what you found.** Examine at least one directly relevant primary-source abstract or paper, and use additional primary sources where possible. Compare the candidate with the **closest known mechanism, application and specialized baseline**. An abstract-only review must say so.
3. **Write a durable dossier** at `PRIOR_ART/PA-P-NNN.md` using [the dossier template](PRIOR_ART/TEMPLATE.md). Record **every executed query verbatim**, date, search provider/tool, and **dated results** (titles, authors/year when available, links/DOIs, brief accurate descriptions and overlap/difference). Include at least **three distinct relevant result records** where available; if fewer, log the actual shortfall and which queries returned no relevant results. **Never fabricate searches, dates, paper access or “no results.”** Keep negative matches and close prior art; do not cherry-pick favorable results. Publisher/source links matter more than invented source counts.
4. **Decide the claim class before computation:** `KNOWN_METHOD_BENCHMARK`, `KNOWN_METHOD_NEW_APPLICATION`, `OPEN_GAP_HYPOTHESIS`, or `NOVELTY_UNVERIFIED`. Write the **nearest known result and the exact unresolved delta**, or state plainly **no novel delta demonstrated**. Novelty is not established merely because three searches failed to find a match. If the same mechanism **and** application are known, do not run it as a claimed discovery: only run a deliberately labelled replication, stronger-baseline benchmark, or genuinely changed application/gap with its own utility rationale.
5. **Commit the complete dossier together with the new P-card**, both cross-linked, **before** the first experiment. The P-card must name its claim class and closest predecessor. Inspect the branch head/read-back; then proceed. **No complete dossier = no new experiment**. If external search is unavailable, mark `PRIOR_ART: BLOCKED` and stop the experiment until access returns. An agent's internal memory, repo citations alone, or promises to search later do not pass.

## When writing an R-card / reporting to the owner

- Link the P-card's **pre-experiment prior-art Git commit** and dossier; report search query provenance, primary sources reviewed, claim class and unresolved difference. Recheck literature if the work unexpectedly resembles a known method; file corrected findings as an amendment, and **downgrade novelty claims promptly**.
- **Never** describe an observed speedup as a newly discovered algorithm when its underlying method is established. “Known technique; new scoped measurement,” “independent replication,” and “candidate extension not yet shown in literature” are valid, distinct results.
- New R-cards require the **10/10 [proof-of-done](PROOF_OF_DONE.md)**, including the auditable literature search. A completed numerical result with missing search is **POD: NO**; numerical `GATE: PASS` does not confer originality. The archival evidence classification (`REPORTED/REPRODUCED/CERTIFIED`) is separate from the *novelty/prior-art* class.
- The dossier is **part of the committed research output**, not merely a citation list or a private chat/search history. Search timestamps and result URLs must survive conversation resets.

## Retrospective example: how the prior failure happened

The [PWM records R-006–R-008](RESULTS/R-008.md) tested a Taylor-polynomial kick on a switched-converter surrogate and only **afterward** identified prior work on polynomial state-transition approximations for buck converters (Luciano and Strollo, **1990**). The [retrospective search record](PRIOR_ART/PA-PWM-RETRO.md) records the actual search queries, results and direct overlap. **It was not a pretest search**, so it cannot repair the old workflow retrospectively. R-008 remains a scoped reported 1.209× benchmark result **using established numerical ideas**, not an invention claim.

**Historical P-000–P-082 / R-001–R-008** retain their original gate/history and nine-box audit, without false pretenses of pretest literature diligence. However, **any future experiment**, including continuation of an old open lead such as P-030, P-040, P-051, P-060 or P-070, must first register a **new linked P-ID and its pretest dossier**. A purely clerical update to old results is not a new experiment.
