Read-only compiler/API audit; no numerical changes, backend changes, unsafe passthrough or ADR changes. CE prototype remains stopped/unpromoted. DEC28 requires the GPU stage's authored numerical source to remain WGSL and wgpu to run it; a compiler emitting stricter native instructions would not itself create a second kernel, but no such current option was found. A dependency/compiler API extension needs deliberate review, not a silent architecture workaround.

Safe patched-SPIRV import is not a supported shortcut: wgpu's safe ShaderSource::SpirV path parses into Naga(front/spv options strict_capabilities=true), and Naga front/spv/mod.rs parse_execution_mode recognizes only supported listed modes; RoundingModeRTE/DenormPreserve fall through to UnsupportedExecutionMode. Naga IR/emitter does not retain these controls. Unsafe passthrough is expressly outside this pass and was not enabled. Likewise WGSL @invariant is not a general arithmetic precision/rounding control.

Primary Vulkan specification confirms absent RoundingModeRTE/RTZ execution mode means implementation-defined rounding. Hardware properties shaderRoundingModeRTEFloat32 and shaderDenormPreserveFloat32 merely indicate the modes can be used; exposing them is not an application request. SelectedRX5700XT/RADV25.1.5 exposes those and RTZ/flush capabilities, so hardware is capable, but current safe compiler API does not select them. https://docs.vulkan.org/spec/latest/appendices/spirvenv.html and https://docs.vulkan.org/refpages/latest/refpages/source/VkPhysicalDeviceFloatControlsProperties.html . WGSL's weaker guarantee remains https://www.w3.org/TR/WGSL/#floating-point-accuracy .

Smallest plausible strict native path is an OPTIONAL scoped Naga/wgpu compiler/API extension (or maintained dependency patch) that keeps WGSL as sole authored kernel, carries a strict FP policy through the validated normal compilation path, emits the required32bit RTE/denorm execution modes/capabilities and appropriate noncontracting arithmetic decorations, and checks Vulkan FloatControls properties before enabling that path. Unsupported backend/device must decline to existing CPU route; no silent global assumptions. Contract for transformations/reassociation and subnormals needs precise SPIR-V review too; adding one flag is not asserted sufficient. Actual emitted-artifact inspection, runtime EFT adversarial checks and whole-frame proof would validate it. Current installed API offers no local safe option to implement this solely in GPU32's call site. Vendoring/forking dependencies or adding raw native submission was NOT done and is not authorized by this research finding.

An empirical CE route may be useful, but sparse self-tests/corpus cannot be relabeled a universal RN arithmetic proof. Parent must decide whether to pursue the scoped compiler-support work, an explicitly honest empirical research contract with appropriate platform guard, or stop. No new ratio/performance inference follows from this audit; prior prototype coldCPU.195s/GPU1.184s at128x72 remains slower, while deepTim coverage8033/9216 is real. Larger representative cold/resident measurements are a future phase, not executed here.
