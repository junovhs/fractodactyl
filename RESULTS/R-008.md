## Original frozen gates

P-082 asks whether the degree-five polynomial input-kick operator from P-081, which showed ~2.027x warm-kernel improvement, yields **at least 1.10x median cold end-to-end speed** over an equally JIT-compiled **exact analytical affine period-return** when reusing one compiled kernel over **2,048 batches x 128 trajectories x 32 periods**, cycling 16 independently seeded input sets (seeds 20261014 through 20261029). Both pay construction/JIT plus all batch computations; shared input creation occurs outside both clocks. Accuracy first: a fresh independent **128-trajectory holdout seeded 20261013**, final-state infinity-norm error **<=1e-7** versus augmented-matrix-exponential oracle, **zero wrong duty regimes**. Three fresh processes per method, chronological order **candidate, exact, exact, candidate, candidate, exact** (C-E / E-C / C-E pairs). Failed accuracy would prohibit timing.

## Frozen equations, data and opponents

Same model as [R-006](R-006.md) and [R-007](R-007.md): `x=(i,v)`, `x'=A x + b_mode`, `A=[[0,-1],[1,-0.5]]`, `b_on=(1,0)`, `b_off=(0,0)`, `T=0.3`; at every period start `d=clip(0.5+0.6(0.5-v)+p,0.2,0.8)`. ON for `Td`, OFF for `T(1-d)`. Candidate: degree-five Taylor expansion about duty 0.5 of the exact affine input kick `A^{-1}(exp(AT)-exp(A T(1-d)))b_on`, with exact clipping. Opponent: Numba-compiled analytical damped rotation, `exp(At)=exp(-t/4)[cos(sqrt(15)t/4) I + sin(sqrt(15)t/4)/(sqrt(15)/4) (A+I/4)]`, applying the same cached `exp(AT)` and exact kick. Both recalculate clipped controller duty from their own state. Oracle: independent SciPy `expm` on each augmented 3x3 ON affine step followed by 2x2 OFF step (not the candidate recurrence).

For any seed `s`, initialize `rng=numpy.random.default_rng(s)`; generate **128** currents uniformly on [0.15,0.35], then **128** voltages uniformly on [0.35,0.65], then **128** parameters uniformly on [-0.35,0.35]. Holdout uses 20261013, repeated-loop datasets use 16 distinct seeds 20261014..20261029; `dataset[j%16]` for `j=0..2047`. New arrays are created **once before timing** for both methods, and identical input arrays are supplied. Each fresh process starts timer immediately before operator chart/constant generation and first JIT compilation, then completes every call. Package imports and input generation are excluded for both, reflecting a prepared-job workload rather than cold Python interpreter startup.

## Interpretation, nonclaims and next edge

**KEEP this ~1.209x measurable total-computation reduction as a scoped research improvement.** It demonstrates why an original one-shot cold >=3x failure ([R-007](R-007.md)) can coexist with a legitimate lower-magnitude, separately preregistered repeated-use win. **It does not show a new general mathematical method, an industrial converter gain, full event-triggered branch certification, or an improvement of the Fractodactyl renderer.** No theorem/validated domain, no independent repo-archived executable, no uncertainty study beyond three fresh process runs.

**Cheapest discriminating next action:** do *not* spend further time raising polynomial degree on this toy. Test representative converter conditions or a continuous state-triggered event (P-030), and compare the complete deployment lifecycle and specialist event solver. Retain this result for future matched realistic workload integration; no claimed compounding with other kernel wins.
